- 第 6 步其余情形全部符合预期：relative / rooted / 无扩展名本地图片出图，missing → `Unavailable`，超尺寸 → `Too large`，远端 HTTPS 与 302 出图，超时 → `Timed out`，非图片 → `Unavailable`，超尺寸 → `Too large`；关掉 `allow_insecure_remote_images` 后四个 http 用例全部 `Blocked by settings`。见 [Step 6](#step-6-images)。
- 第 9 步全部通过：front matter、fence 内容和 `#hashtag` 都不算标题，闭合 `#` 被裁掉，setext 两级都识别；caret 移动、实时输入的标题、点击顶/中/底部条目、三个 outline 同开、zoom 与关闭都符合预期。见 [Step 9](#step-9-the-outline-panel)。
- 三个已知差异照旧记录：Windows 忽略 POSIX 权限位；浏览器内点击锚点未驱动；scheme 切换下的重取由 Linux 记录覆盖。见 [Not claimed](#not-claimed)。

## Method

The app is the real Windows Sublime Text, not the test suite. A throwaway
package, [`probe.py`](windows-2026-09-06/probe.py), runs a generator on the UI
thread and posts each phase's JSON to a host collector at `10.0.2.2:8099` over
QEMU's user-mode NAT — there is no shared filesystem with the guest.
[`collector.py`](windows-2026-09-06/collector.py) writes the JSON, splits any
exported page out into its own `.html`, screendumps the guest through the QEMU
monitor, and only then answers `go`, so each picture belongs to the phase that
posted it. [`imgserver.py`](windows-2026-09-06/imgserver.py) serves the five
fixed remote-image endpoints step 6 needs. [`w.ps1`](windows-2026-09-06/w.ps1)
lays a run out in the guest and starts the editor.
[`check.py`](windows-2026-09-06/check.py) and
[`check-steps-6-9-10.py`](windows-2026-09-06/check-steps-6-9-10.py) assert on
the host against what came back.

Five things cost a run each and are worth writing down:

- **A probe package with no `.python-version` loads into the 3.3 plugin host.**
  `sys.version` came back `3.3.7`, `typing` was missing, and nothing inside
  MarkdownGlance's own 3.8 session was reachable. `window.run_command` still
  worked across hosts, so the first four phases looked fine and only the fifth
  failed. The probe now ships `.python-version` = `3.8`.
- **`HKCU\Software\Policies\Microsoft\Edge` is denied to a non-elevated user.**
  Setting `HideFirstRunExperience` there killed the whole provisioning script.
  Pre-starting Edge with `--no-first-run --no-default-browser-check` does the
  same job without elevation.
- **A screendump pauses the guest, and a paused guest drops keystrokes.** With
  the collector posting every second or two, a command typed into the Run
  dialog came out as `poweshel -p bpas -Fle :\w.s1 Suie otlie`. Stop the
  collector before typing the launch command, and screendump the Run dialog to
  read the line back before pressing Return.
- **`Stop-Process` did not close the editor once**, and the run then continued
  inside the previous session, with its tabs, its groups and its old probe
  still ticking. `w.ps1` now uses `taskkill` and waits for the process to go,
  and throws rather than running on. The probe also carries a load generation,
  because Sublime reloads a package's plugins when their files change and the
  old probe's timer chain survives that: without the generation, two probes
  drove the same window and the finished one reposted its last phase forever.
- **A synchronous `SetWindowPos` from the plugin host deadlocks the guest.**
  The editor's UI thread waits for the plugin callback to return; the callback
  waits for that UI thread to handle `WM_WINDOWPOSCHANGING`. The window resize
  now runs on a worker thread with `SWP_ASYNCWINDOWPOS`, which is what made the
  `widths` re-run possible.

## Step 6: images

The fixture is generated by the probe, one labelled list item per case, so each
result can be read back by label out of the rendered body. Twelve cases, under
`allow_insecure_remote_images` on and then off:

| Case | Source | http allowed | http blocked |
| --- | --- | --- | --- |
| relative | `pixel.png` | image 160x64 | image |
| absolute-drive | `C:/Users/…/pixel.png` | **Unavailable** | **Unavailable** |
| absolute-rooted | `/Users/…/pixel.png` | image 160x64 | image |
| absolute-file-url | `file:///C:/Users/…/pixel.png` | **Unavailable** | **Unavailable** |
| missing | `nope.png` | Unavailable | Unavailable |
| oversized-local | 8000x8000 header | Too large | Too large |
| extensionless | `pixel-noext` | image 160x64 | image |
| remote-https | `https://latex.codecogs.com/png.latex?a` | image | image |
| remote-redirect | 302 to `/ok.png` | image 160x64 | Blocked by settings |
| remote-timeout | server sleeps 20s, timeout 3s | Timed out | Blocked by settings |
| remote-invalid | text served as `image/png` | Unavailable | Blocked by settings |
| remote-oversized | 8000x8000 header | Too large | Blocked by settings |

Everything except the two absolute spellings is what the step asks for. The
extensionless case proves the magic-byte detection: the file has no suffix and
still decodes. The oversized cases are a PNG header that declares 8000x8000,
which exceeds `remote_max_dimension` (4096) — the fetcher rejects them on the
declared size without decoding a body.

The remote cases other than `remote-https` are plain HTTP to the host's
`imgserver.py` with `allow_insecure_remote_images` on. That is a deviation from
the step's wording, which says HTTPS: an HTTPS server would need a certificate
in the guest's trust store. The fetcher code path is the same one; only the
scheme check differs, and the second column exercises that check directly.

### Finding 1: absolute local image paths do not resolve on Windows

`![x](C:/Users/tester/Desktop/images/pixel.png)` renders as `Unavailable`. So
does the `file:` URL spelling. Only a path rooted without a drive letter works.
Confirmed against the code rather than guessed:

- `urlsplit("C:/Users/…")` returns `scheme='c'`, and
  `structure._asset_key` drops anything with a scheme it does not know:
  `if parsed.scheme or source.startswith("data:"): return None`. With no asset
  key the image gets the `Unavailable` placeholder.
- `file:///C:/Users/…` gives `path='/C:/Users/…'`, and
  `HOST.normalise` is `ntpath.realpath`, which turns that into
  `\C:\Users\tester\Desktop\images\pixel.png` — a rooted path on the current
  drive with a literal `C:` directory in it. The open fails.
- `/Users/…` works only by accident of `ntpath.join(base, "/Users/…")`
  inheriting the drive from the source file's directory.

This is Windows-only: on Linux the step's absolute case is `/home/…`, which has
no scheme and no drive letter, so it takes the working path. A fix belongs in
`_asset_key`: treat a single-letter scheme followed by `/` or `\` as a Windows
drive, and strip the leading separator from a `file:` path that starts with a
drive letter.

### Finding 2: the outline is carved out of the table of contents' group

With both panels open, neither is wide enough to show an entry.
[The screenshot](windows-2026-09-06/w1-long-auto_width-True.png) shows the long
table-of-contents entry broken over six lines and the outline reduced to a
sliver a few characters wide; with short headings and `auto_width` on it is
worse, at 95 px and 30 px. Step 10's "no entry may wrap" does not hold in this
configuration.

The cause is in `LayoutOwner.acquire_beside`. It walks `rightmost_in_row` from
the source group so that the outline never lands as a second tab beside the
preview — but when a table of contents is open, the rightmost group *is* the
table of contents, so the outline splits that instead of the source. The
measured columns say so exactly: `[0.0, 0.5, 0.825, 0.9475, 1.0]`, where
`0.9475 = 1 - (1 - 0.825) * 0.3` and `0.3` is `ROLE_SHARE[OUTLINE]`. From then
on `share_for` caps each panel at its role share **of that already narrow
pair**, and `ROLE_MINIMUM` is a fraction of the same pair, so neither floor nor
fit can recover: the width followed neither a zoom to 1.5 nor an added
84-character heading.

**This is not a Windows result — confirmed on Linux.** The same fixture opened
the same way in the portable Sublime Text 4200 of
the local `run-markdownglance` harness gives
**the same columns to the digit**: `[0.0, 0.5, 0.825, 0.9475, 1.0]`, table of
contents 161 px and outline 59 px on that host's narrower window, with the long
entry wrapped over seven lines and the outline reduced to two characters
([scenario](windows-2026-09-06/linux-confirmation/linux-widths.py),
[numbers](windows-2026-09-06/linux-confirmation/with-toc-widths.json),
[screenshot](windows-2026-09-06/linux-confirmation/with-toc.png)). The pixel
figures differ from Windows only because the window is smaller; the fractions
are identical, which is what the shared arithmetic predicts.
[`layout-replay.py`](windows-2026-09-06/layout-replay.py) reproduces the same
shape a third time, on the host, with no editor at all.

**The table of contents is the cause, not the group count.** The companion
scenario opens the same document, the same preview and the same outline with
`enable_toc` off
([scenario](windows-2026-09-06/linux-confirmation/linux-widths-notoc.py),
[numbers](windows-2026-09-06/linux-confirmation/no-toc-widths.json),
[screenshot](windows-2026-09-06/linux-confirmation/no-toc.png)). The outline
then splits the preview's group instead, the columns are `[0.0, 0.5, 0.85, 1.0]`
and the outline is **203 px** — against 59 px for the identical document with
the table of contents open. Same host, same window, same setting.

The same panels are fine on their own: on Windows, with no table of contents
open, the outline fitted to 191 px, and a hand-drag took it to 280 px,
which does show the long entry. A fix probably means anchoring the outline on
the source group and letting the split walk past groups the plugin owns, or
sizing the two panels against the window rather than against each other.

## Not claimed

- **File modes are a Linux claim.** The exported page is `0o100666` and its
  directory `0o40777`: Windows ignores the mode argument to `os.open` and
  `os.makedirs`. What protects the file here is the ACL on the user's own
  `%LOCALAPPDATA%\Temp`, which was not inspected. Step 12's "mode 600" check
  should stay marked Linux-only.
- **Anchor clicking inside the browser** was not driven on Windows; the page was
  asserted to have the ids and the links. A click selecting the right `:target`
  is covered by the Linux HTTP check in
  [manual-2026-09-06](manual-2026-09-06.md#http-follow-up).
- **A colour-scheme change under an open preview** was not repeated here. The
  re-render on a scheme change is covered by [math-2026-09-06](math-2026-09-06.md).
- **Finding 2 on macOS.** Windows and Linux both reproduce it, in a real
  editor, with identical columns. macOS was not tested; the arithmetic is the
  same, so there is no reason to expect it to differ.
- **The drag in `w3`** was issued through `window.set_layout` rather than the
  mouse, so it was not bounded the way a real drag is; it put the table of
  contents' cell below any width a user could reach, and the group left behind
  after the reopen is an artefact of that, not a product claim. The claim
  `w3` does support is that the automatic fit comes back after a close and
  reopen.
- **Steps 1–5, 8, 11 and 13–15** were not run in this session. Tables, the
  table of contents and Mermaid were exercised on this guest when it was built
  (2026-08-29), against the tree as it stood then — before 0.4.0 replaced the
  vendored parser. Those results predate the Markdown-library change and should
  not be carried forward to 0.4.2.
- The libraries were copied into `Lib\python38` off the CD rather than
  installed by Package Control, because this guest carries a manual install.
  The Package Control install path is covered on Linux by
  [manual-2026-09-06](manual-2026-09-06.md#step-13-add-repository-install).

## Plan observations

- Step 12's last sentence is Linux-specific. It should read something like
  "On Linux, `ls -l` the page under `$TMPDIR/MarkdownGlance` and confirm mode
  600; on Windows the mode is not honoured and the file inherits the user's
  Temp ACL."
- Step 12 asks for "both a light and a dark system theme". Worth saying
  explicitly that the exported file must not differ between them — that is the
  cheaper and stronger check.
- Step 6's "absolute" case should name the spelling. On Windows there are three
  and they do not behave the same; the step passes or fails depending on which
  one the tester picks.
- Step 9 should say that the toggle closes the outline only from the panel.
  From the source view it focuses it, and a tester who presses the shortcut
  twice from the source will report that it does not close.
- Step 10 should state the panel combination it means. Measured here, the
  outline alone fits; the outline beside a table of contents does not, and the
  step reads as though the two cases were the same test.
